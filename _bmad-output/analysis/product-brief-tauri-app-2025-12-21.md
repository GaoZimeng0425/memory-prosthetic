# Product Brief: Memory Prosthetic

**Date:** 2025-12-21
**Author:** Gao

---

## Executive Summary

**Memory Prosthetic** 是一款 **「记忆外挂」** 应用 —— 让模糊的记忆变成精确的检索。

通过浏览器插件一键收集网页内容，结合 AI 语义理解和 Spotlight 级快速唤起，解决现代人 **"我看过但找不到"** 的知识焦虑。

**核心定位：想到即找到，看过不再忘。**

与 Cubox、Notion 等工具不同，本产品不以"收藏"或"阅读"为核心，而是以 **「检索记忆」** 为核心价值——你的第二大脑，随时待命。

---

## Core Vision

### Problem Statement

现代知识工作者每天接触海量信息——技术文章、产品灵感、学术论文、新闻观点。然而：

- **收藏即遗忘**：信息被存入 Notion、书签夹后再也不会被看到
- **搜索靠记忆**：必须记住精确关键词才能找到内容
- **知识成孤岛**：收集的内容之间没有关联，无法形成体系
- **访问成本高**：打开应用、翻找层级，阻力太大

**痛点本质**："我确定看过这个，但不记得在哪看的，也不记得具体说了什么。"

### Problem Impact

- 重复搜索同样的问题，浪费时间
- 无法在讨论中引用有力论据
- 学习积累无法复利，知识碎片化
- 产生信息焦虑，收藏越多越心慌

### Why Existing Solutions Fall Short

| 产品 | 优势 | 不足 |
|------|------|------|
| **Notion Web Clipper** | 生态强大 | 无 AI 整理、搜索弱、启动慢 |
| **Cubox** | 阅读体验好 | 侧重阅读非知识管理、无知识图谱、无快速启动 |
| **Readwise/Reader** | AI 高亮优秀 | 重阅读轻体系、云端定价高 |
| **Obsidian** | 本地+图谱 | 手动整理成本高、无浏览器快捷收集 |

**市场空白**：没有一款产品把 **「模糊记忆 → 精确检索」** 作为核心价值。

### First Principles Foundation

**不可争辩的事实：**

1. 人的记忆是模糊的 — "那篇文章讲了什么来着" 是真实体验
2. 检索成本决定使用频率 — 如果找东西太麻烦，就不会去找
3. 收藏 ≠ 知识 — 存了不等于学了，看了不等于记了
4. 注意力是稀缺资源 — 任何增加认知负担的功能都会被放弃
5. 知识的价值在于连接 — 孤立的信息不如有关联的知识

**核心价值公式：**

```
产品价值 = 搜索速度 × 搜索准确率 × 启动便捷性
```

### Proposed Solution

一款 Tauri 构建的本地桌面应用，功能按优先级分层：

| 层级 | 功能 | 验证假设 |
|------|------|----------|
| **P0 核心循环** | 快捷唤起 + 语义搜索 | 模糊记忆能找到内容 |
| **P1 输入层** | 浏览器插件 + 链接分享 | 低阻力收集 |
| **P2 增强层** | AI 摘要/标签 | 提升搜索准确率 |
| **P3 探索层** | 知识图谱/主动推荐 | 发现遗忘的关联 |

**技术选型优势**：

- Tauri 本地应用 → 数据隐私、离线可用、启动迅速
- 本地 AI 推理可选 → 无需担心云端隐私
- 本地优先 + 可选加密同步 → 兼顾隐私和多设备

### Key Differentiators

| 差异化维度 | 我们的优势 |
|------------|------------|
| **核心价值** | 不是收藏工具，是"记忆外挂" |
| **启动速度** | Spotlight/Raycast 级别，全局快捷键 0.3s 唤起 |
| **搜索方式** | 语义搜索，支持模糊记忆检索 |
| **AI 原生** | 从 Day 1 以 AI 为核心设计 |
| **本地优先** | 数据在本地，隐私有保障 |

### Minimum Viable Product (MVP)

**2 周验证核心假设的最小功能集：**

1. ⌨️ 全局快捷键唤起搜索框
2. 🔍 语义搜索（基于 embedding）
3. ➕ 简单的内容添加（URL + 标题 + 手动摘要）
4. 📚 10-50 条测试内容

**验证指标：** 自己使用 1 周，是否真的"想到就找到"？

**成功标准：** 每天主动使用 3+ 次搜索，且 80% 能找到目标内容。

## MVP Scope

### Core Features（MVP 必须实现）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| **全局快捷键唤起** | Cmd/Ctrl + 自定义键，0.3s 内弹出搜索框 | P0 |
| **语义搜索** | 基于 embedding 的模糊搜索，支持中英文 | P0 |
| **Chrome 浏览器插件** | 一键收集当前网页到应用 | P0 |
| **内容存储** | URL + 标题 + 正文内容本地存储 | P0 |
| **搜索结果展示** | 显示匹配的文章列表，点击可跳转原文 | P0 |

**MVP 核心循环：**

```
看到好文章 → Chrome 插件一键收集 → 内容同步到应用
     ↓
需要时 → 快捷键唤起 → 输入模糊关键词 → 找到文章 → 点击跳转
```

### Out of Scope for MVP（明确不做）

| 功能 | 原因 | 计划阶段 |
|------|------|----------|
| **AI 自动摘要/标签** | 先验证搜索核心价值 | Alpha |
| **知识图谱可视化** | 需要足够内容积累后才有意义 | Beta |
| **多设备同步** | 复杂度高，先专注单机体验 | Beta |
| **移动端应用** | 桌面优先，移动端优先级低 | Future |
| **Safari/Firefox 插件** | Chrome 覆盖主流用户 | Beta |
| **AI 教学/思维导图** | 属于未来愿景，非当前核心 | Future |
| **团队协作** | 个人工具优先 | Future |
| **数据导入导出** | 先跑通核心，再考虑迁移 | Alpha |

**MVP 哲学：**

> 宁可功能少但体验好，不要功能多但都半成品。

### MVP Success Criteria（成功门槛）

**MVP → Alpha 的决策点：**

> 如果 MVP 阶段自己每天都在用，且搜索成功率 ≥ 80%，则进入 Alpha 阶段开发 AI 增强功能。
