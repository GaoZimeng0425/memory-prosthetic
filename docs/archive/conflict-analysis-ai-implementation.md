# AI 实现冲突分析报告

**生成时间：** 2025-12-25
**分析范围：** PRD vs 技术规范 vs 实际实现

## 执行摘要

发现 **3 类主要冲突**，涉及 AI 模型选择、算法实现方式和性能要求。需要更新 PRD 以反映当前仅使用云端 AI 的架构决策。

---

## 冲突 1: AI 模型选择策略

### PRD 要求

- **FR167**: 系统可以支持本地 Embedding 模型（如 all-MiniLM-L6-v2，23MB）
- **FR169**: 系统可以支持本地摘要生成模型（如 Phi-2，可选）
- **FR170**: 系统可以支持可选云端 API（用户自带 API Key，如 OpenAI、Anthropic）
- **FR171**: 用户可以在设置中选择 AI 模型：**本地模型、云端 API、混合模式**
- **FR196**: 系统可以在网络 API 调用失败时，**自动切换到本地模型**

### 技术规范实现

- **架构说明**：所有 AI 处理在前端使用 Vercel AI SDK (`ai` 包) 直接调用云端 API，**不进行本地推理**
- **实现位置**：`packages/ai` 包
- **支持提供商**：OpenAI、Anthropic、自定义 API 端点

### 实际实现

```typescript
// packages/ai/src/config.ts
export type AiProvider = 'openai' | 'anthropic' | 'custom'
// 仅支持云端 API，无本地模型选项
```

### 冲突级别：🔴 **严重**

**影响：**

- PRD 承诺的功能（本地模型、混合模式）无法实现
- 用户无法在离线环境下使用 AI 功能
- 降级策略（FR196）无法实现

**建议：**

1. **更新 PRD**：将 FR167、FR169、FR171、FR196 标记为"已取消"或"未来版本"
2. **添加说明**：明确当前版本仅支持云端 AI，本地模型为未来规划
3. **更新性能要求**：FR185 从"< 3 秒（本地模型）"改为"< 5 秒（云端 API）"

## 冲突 2: 算法实现方式

### PRD 要求

#### 标签生成（FR128-FR129）

- **FR128**: 系统可以基于内容语义（**Embedding 聚类**）生成标签
- **FR129**: 系统可以基于关键词提取（**TF-IDF/TextRank**）生成标签

#### 关键词提取（FR147-FR148）

- **FR147**: 系统可以基于 **TF-IDF 算法**提取关键词
- **FR148**: 系统可以基于 **TextRank 算法**提取关键词
- **数据模型**：`extraction_method: TEXT (tfidf/textrank，提取方法)`

#### 主题识别（FR154-FR155）

- **FR154**: 系统可以基于 **Embedding 聚类**识别主题
- **FR155**: 系统可以基于 **LDA（潜在狄利克雷分配）**识别主题

### 技术规范实现

- **标签生成**：使用 `generateObject` + Zod Schema，AI 生成
- **关键词提取**：使用 `generateObject` + Zod Schema，AI 生成，`extractionMethod: 'ai'`
- **主题识别**：使用 `generateObject` + Zod Schema，AI 生成

### 实际实现

```typescript
// packages/ai/src/keywords.ts
export type Keyword = {
  extractionMethod: 'ai'  // 固定为 'ai'，不支持 'tfidf' | 'textrank'
}

// packages/ai/src/tags.ts
// 仅使用 AI 生成，无 Embedding 聚类或 TF-IDF/TextRank 实现
```

### 冲突级别：🟡 **中等**

**影响：**

- PRD 承诺的多种算法选择无法实现
- 数据模型中的 `extraction_method` 字段只能为 'ai'
- 用户无法选择不同的算法策略

**建议：**

1. **更新 PRD**：将 FR128、FR129、FR147、FR148、FR154、FR155 标记为"使用 AI 生成"或"未来版本"
2. **更新数据模型**：将 `extraction_method` 改为仅支持 'ai'，或添加说明
3. **添加说明**：明确当前版本使用 AI 生成，传统算法为未来规划

## 冲突 3: 性能要求

### PRD 要求

- **FR184**: 系统可以在内容收集后 **5 秒内**开始 AI 处理
- **FR185**: 系统可以单篇内容的 AI 处理时间 **< 3 秒（本地模型）**
- **FR1221**（非功能性需求）：AI 摘要生成 < 3s（本地模型）

### 技术规范实现

- **性能要求**：
  - AI 摘要生成：< 5s（云端 API 调用）
  - AI 标签生成：< 5s（云端 API 调用）
  - AI 内容分类：< 5s（云端 API 调用）
  - 关键词提取：< 5s（云端 API 调用）
  - AI 主题识别：< 5s（云端 API 调用）

### 冲突级别：🟡 **中等**

**影响：**

- 性能指标不一致（3s vs 5s）
- 性能基准不同（本地模型 vs 云端 API）

**建议：**

1. **统一性能要求**：将 PRD 中的 FR185 和 FR1221 更新为"< 5s（云端 API）"
2. **添加说明**：云端 API 响应时间受网络影响，5s 为合理上限

## 总结

### 冲突统计

- 🔴 **严重冲突**：1 个（AI 模型选择策略）
- 🟡 **中等冲突**：2 个（算法实现方式、性能要求）
- ✅ **已正确实现**：5 个功能模块
- ⚠️ **部分实现**：2 个功能模块

### 建议行动

1. **立即更新 PRD**：标记已取消的功能，更新性能要求
2. **添加架构说明**：在 PRD 中明确当前版本仅支持云端 AI
3. **更新数据模型**：调整 `extraction_method` 字段说明
4. **完善实现**：补充用户控制 UI 和错误日志记录

### 风险评估

- **低风险**：性能要求差异（3s vs 5s）可接受
- **中风险**：算法选择缺失，但 AI 生成质量通常更好
- **高风险**：本地模型缺失，影响离线使用和降级策略
