# 前端架构重构 - 实施计划

本计划将分 4 个阶段实施，总计约 **10-14 个工作日**。

## 📅 分阶段实施计划

### 🔥 阶段 1：关键问题修复（第 1-2 周）

#### 第 1-3 天：IPC 通信优化
**为什么优先：**
- 影响所有 API 调用
- 后端改动需要时间
- 是其他优化的基础

**步骤：**
1. Day 1 AM: 优化 TauriAdapter（前端）
2. Day 1 PM: 编写单元测试
3. Day 2: 修改后端命令签名
4. Day 3: 集成测试和调试

**验收标准：**
- [ ] 所有 API 调用正常工作
- [ ] 性能提升 50%+
- [ ] 无控制台错误

---

#### 第 4-5 天：轮询策略优化
**为什么优先：**
- 立即提升用户体验
- 减少资源消耗
- 为乐观更新打基础

**步骤：**
1. Day 4 AM: 移除所有 `refetchInterval`
2. Day 4 PM: 添加窗口焦点刷新
3. Day 5: 添加后端事件系统

**验收标准：**
- [ ] 无定时轮询
- [ ] 窗口切换时刷新
- [ ] 事件驱动更新工作

---

#### 第 6-7 天：Mutation 乐观更新
**依赖：** 轮询优化（需要事件系统）

**步骤：**
1. Day 6: 实现基础乐观更新（setFavorite, toggleStar）
2. Day 7: 实现复杂乐观更新（archive, delete）

**验收标准：**
- [ ] 操作立即响应
- [ ] 失败正确回滚
- [ ] UI 无闪烁

---

### 🛠️ 阶段 2：代码重构（第 3 周）

#### 第 8-9 天：DialogContext 重构
**为什么延后：**
- 不影响功能
- 需要仔细测试
- 可以渐进式迁移

**步骤：**
1. Day 8: 创建新的组合式 Dialog 组件
2. Day 9: 逐步迁移使用点，删除旧代码

**验收标准：**
- [ ] 所有 Dialog 正常工作
- [ ] 无全局状态污染
- [ ] 支持多个同类型 Dialog

---

#### 第 10 天：路由文件合并
**独立任务：** 可以并行进行

**步骤：**
1. 创建路由布局结构
2. 迁移详情页到统一路由
3. 测试所有路由

**验收标准：**
- [ ] 16 个文件减少到 9 个
- [ ] 所有路由正常工作
- [ ] 无 404 错误

---

#### 第 11 天：__root.tsx 拆分
**独立任务：** 可以并行进行

**步骤：**
1. 提取窗口管理、快捷键等组件
2. 简化根组件
3. 编写测试

**验收标准：**
- [ ] 文件从 400+ 行减到 ~100 行
- [ ] 所有功能正常
- [ ] 有单元测试覆盖

---

### 🚀 阶段 3：性能优化（第 4 周）

#### 第 12-13 天：模糊搜索后端化

**步骤：**
1. Day 12: 实现 SQLite FTS5 全文搜索

**验收标准：**

## 🚨 风险管理

### 高风险项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| IPC 修改导致 API 不工作 | 高 | 保持向后兼容，分阶段迁移 |
| DialogContext 重构影响功能 | 中 | 并行运行新旧代码，逐步切换 |
| 后端事件系统不稳定 | 中 | 保留窗口焦点刷新作为降级方案 |

### 回滚计划

每个阶段完成后创建 git tag：
```bash
git tag -a phase1-complete -m "IPC 优化完成"
git tag -a phase2-complete -m "代码重构完成"
```

如遇问题可快速回滚：
```bash
git checkout phase1-complete
```
